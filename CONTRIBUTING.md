# Contributing

Start with a concrete artifact, root, declared contract and expected behavior. Preserve permission to share the artifact and its original license. A useful contribution reproduces a supported-input failure, improves dependency diagnosis, adds a justified ABI/import capability or makes the Studio clearer.

Include a focused regression or independent control that checks the changed behavior. Keep unsupported behavior explicit. Do not add silent stubs, guessed prototypes or universal-support claims. The runtime and exported licenses/source must travel together.

Run the applicable commands in README.md. Report what passed and what was unavailable. Disclose substantial AI assistance and verify submitted claims yourself. For a suspected security vulnerability, use the private route in SECURITY.md.
